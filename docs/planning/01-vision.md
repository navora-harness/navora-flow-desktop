# 01 — 产品愿景与定位

## 1. 定位

| 维度 | 选择 |
|------|------|
| 形态 | **本地桌面应用**（优先 Windows；后续可扩 macOS/Linux） |
| 交互 | **节点图编辑器**：拖拽方法节点，连线组成流程 |
| 执行 | **本地流程运行时**：一键运行 + **流程 Debug**（断点 / 单步 / 检视端口值） |
| 扩展 | **第三方运行库（插件）**：声明方法（节点）、能力、依赖 |
| 与 AI | **可选**，非核心。可以有「AI 帮写节点」类辅助，但产品本体不是 Agent |

一句话对标：

> **苹果捷径的易用性** + **Unreal Blueprints 的「执行线 / 数据线」清晰度** + **Node-RED 的节点市场与本地运行** + **Navora 式可安装运行库**。

## 2. 核心用户故事

1. **拼流程**：打开空白图，从工具箱拖入 `main` → `Decode.Base64` → `Image.DetectFaces` → `exit`，点运行，看结果面板。
2. **装库**：导入 `image-vision-1.2.0.zip`，依赖的 `codec-core` 自动提示安装；装完后左侧出现「图像识别」分类与一批节点。
3. **库互依赖**：`image-vision` 依赖 `tensor-runtime`；`ocr-cn` 又依赖 `image-vision`。宿主按 DAG 解析版本，加载顺序正确，冲突有明确报错。
4. **复用**：把一段子图画成「子流程 / 函数节点」，在其他流程里调用。
5. **调试**：对流程图 Debug——节点断点、Continue/单步/停止、高亮当前节点与 exec 边、检查每个端口上的 Inputs/Outputs；Run 模式结束后也能点节点回看上次 IO。

## 3. 明确「不是什么」（非目标）

| 不做（至少 MVP 不做） | 原因 |
|----------------------|------|
| AI Agent / 对话驱动工具调用 | 那是 Navora；本产品是人编排、机器执行 |
| 云端 SaaS 工作流（Zapier 替代） | 优先本地算力、本地文件、本地库 |
| 完整 BPMN / 企业审批流 | 过重；先做可编程流程 |
| 无代码面向商务人员的表单编排 | 目标用户偏开发者 / 创作者 / 逆向与多媒体工具用户 |
| 浏览器自动化主战场 | 可作为后续运行库，不是宿主内核 |

## 4. 产品差异化（相对捷径 / Node-RED / n8n）

1. **运行库 = 一等公民**：不是「装 npm 包再手写节点」，而是导入包 → 清单驱动 → 编辑器立刻出现方法节点。
2. **库之间可声明依赖**（像软件包管理），含版本范围与冲突策略。
3. **控制流与数据流分离**（学 Blueprints）：白色执行口 + 彩色数据口，避免 Node-RED 纯 message 流在复杂分支时难读。
4. **面向计算型节点**：编解码、图像、密码学、协议解析等「方法库」，而不只是「连 SaaS」。
5. **桌面原生体验**：文件对话框、本地 GPU/原生扩展（后续）、便携目录。
6. **流程级 Debug**：不是打日志碰运气，而是像 IDE 一样停在节点上看数据（详见 [09-debug.md](./09-debug.md)）。

## 5. 命名（已定）

| 项 | 值 |
|----|-----|
| **产品名** | **Navora Flow** |
| **含义** | Navora 产品线的可视化流程执行器（非 AI Agent） |
| **主仓库名** | 三仓：`navora-flow-desktop` / `navora-flow-library-sdk` / `navora-flow-libraries` |
| **工程扩展** | `.nflow/` 目录 |
| **appId（草案）** | `com.navora.flow`（与 Navora `com.navora.app` 同族） |
| **运行库包后缀** | `.nlib.zip` |
| **CLI 前缀** | `nf-lib` / `nf` |

与 Navora（desktop / plugin-sdk / plugins）同款拆分；规划文档放在 `navora-flow-desktop/docs/planning/`。

未采用：单仓 monorepo；VFlow / Visual Flow（市面已有 ETL 等产品占用该名，易撞名）。

## 6. 成功标准（MVP）

- 能用内置节点跑通：`main → 字符串处理 → 条件分支 → exit`
- 能导入一个第三方库（例如编解码），节点出现在面板并可连线运行
- 能声明 `B dependsOn A`，只装 B 时提示并安装 A
- 流程可保存 / 打开为单一项目文件（JSON 或包目录）
- 运行失败时指出是哪个节点、什么错误
- Run 结束后可点任意已执行节点查看 **上次 Inputs/Outputs**（Debug 最小可用形态）
