# 02 — 市面同类产品对比

## 1. 对照表（按你的目标加权）

| 产品 | 范式 | 插件/节点扩展 | 依赖管理 | 执行模型 | 适合借鉴 |
|------|------|---------------|----------|----------|----------|
| **Apple Shortcuts** | 线性动作列表 + 分支 | 系统/App Intent，弱 | 无 | 顺序控制流 | 易用性、动作参数表单、输入输出 |
| **macOS Automator** | 动作流水线 | 有限 | 无 | 顺序 | 历史教训：扩展难、调试弱 |
| **Node-RED** | 事件/消息数据流 | 社区节点海量（npm） | npm 级，偏松 | msg 传递 | 节点面板、部署、flow JSON、市场 |

## 2. 范式选择建议（关键决策）

你的场景（编解码、图像识别、库方法互相调用）更接近 **可编程计算图**，而不是 Zapier 式「连 SaaS」。

**推荐主范式：Blueprints 式「控制流 + 数据流」双线模型**

```text
[main]──exec──▶[Decode.Base64]──exec──▶[Vision.Detect]──exec──▶[exit]
                    │ data out               │ data out
                    └──────────▶─────────────┘
```

| 备选 | 何时考虑 |
|------|----------|
| 纯 Node-RED msg 流 | 若主场景是事件/IoT/消息管道 |
| 纯捷径式列表 | 若只要简单顺序、不要图 |

MVP 可先做：**单入口 `main`、单向执行、数据口必连或可常量**，复杂事件源（定时、webhook）后期再加。

## 3. 各产品可抄的具体点

### Apple Shortcuts
- 每个动作一个清晰参数表单
- 「魔法变量」= 上游输出引用（我们用数据口连线更直观）
- 运行结果预览

### Node-RED
- 左侧节点树按分类
- 一键 Deploy / 我们改为「运行」+ 自动保存草稿
- `flows.json` 可分享
- 子流程（subflow）= 可复用复合节点

### n8n
- 节点右侧属性面板体验成熟
- 运行时高亮「当前节点」
- **每次运行保留节点输出，点选回看**（本产品 Run 模式应对齐）
- 错误出口 / 重试（后期）

### Blueprints
- Exec 口与 Data 口分离，分支清晰
- Pure 节点（无副作用、按需求值）可后期引入
- 编译期类型检查：口对口类型不匹配则禁止连线
- **调试时针脚值与断点停在节点上**（本产品 Debug 对齐此体验）

### FlowGram / LogicFlow（工程侧）
- 若继续 Vue 技术栈：优先评估 **LogicFlow** 或 **@vue-flow/core**，而不是强上 React Flow
- FlowGram 的变量作用域与表单引擎可参考，不必整框搬

### Navora（你已有的资产）
- `plugin.json` + zip 导入 + 外链热更
- SDK + CLI 编译产物
- 权限/能力申报（本产品可简化为「能力声明」：fs / net / native / gpu）
- **不要**复用 Agent tool-calling 主路径；运行库应注册的是 **Graph Node（方法）**，不是 ChatCompletionTool

## 4. 市场空白（你的切入点）

多数工具要么：

- **自动化/SaaS 集成**（n8n、Zapier），弱于本地重计算库；要么  
- **IoT 消息流**（Node-RED），弱于「方法库依赖图」；要么  
- **游戏/引擎蓝图**（UE），不面向通用桌面工具链。

**「带依赖解析的本地方法运行库 + 双线图编辑器」** 是相对清晰的产品缝隙，尤其适合加密、协议、多媒体、CV 等插件生态。
